# Green & Tasty — Frontend · Домашнє завдання EPAM IT Marathon 6.0

Цей репозиторій містить виконане домашнє завдання фронтенд-треку марафону **EPAM IT Marathon 6.0** (додаток для ресторану *Green & Tasty* на Angular 22).

---

##  Опис виконаної роботи (від автора)

У рамках завдання я реалізував повний функціонал для **Owner Flow** (керування спільним попереднім груповим замовленням у ресторані), пройшовши практичне завдання, усі 3 рівні складності та бонусний трек.

### 1. Практичне завдання & 1-й рівень — Верстка екрана Owner Review
* **Компонент картки учасника (`ParticipantCardComponent`):**
  * Створено автономний (Standalone) компонент картки з динамічним обчисленням заголовка через Angular Signals (`computed`).
  * Реалізовано відображення страв із фото або круглим бейджем першої літери назви страви.
  * Додано бейджі статусу готовності кошика: `Submitted` (зелений) та `Still choosing` (помаранчевий).
  * Розраховано та виведено `Subtotal` для кожного гостя з форматуванням цін через `CurrencyPipe`.
* **Сторінка та адаптивна верстка (`GroupOrderPageComponent`):**
  * Створено головну сторінку та зареєстровано маршрут `/reservations/:reservationId/group-order`.
  * Зверстано інформаційну шапку: назва, адреса ресторану, дата та часовий інтервал, лічильник гостей.
  * Усі кольори та стилі оформлено згідно з макетом Figma з системної палітри проєкту (`app/shared/styles/abstracts/colors` через `@use ... as color`).
  * Забезпечено адаптивність екрана для мобільних пристроїв (від 375 px).

---

### 2. 2-й рівень — Груповий Pre-Order на мок-бекенді
* **Сервіс `GroupOrdersService`:**
  * Реалізовано методи для повної взаємодії з бекендом:
    * `getGroupInvite$(reservationId)` — двоетапне отримання токена та деталей запрошення;
    * `getSessions$(groupReservationId)` — список учасників та їхніх страв;
    * `getOwnerSessionId$(reservationId)` — ідентифікатор сесії овнера;
    * `getStatus$(groupReservationId)` — перевірка статусу групи (`Open` / `Submitted`);
    * `submit$(groupReservationId, reservationId)` — відправка фінального замовлення.
* **Бізнес-логіка сторінки:**
  * Завантаження даних за динамічним `reservationId` з адреси сторінки.
  * Власна картка організатора автоматично позначається як **`My Pre-Order`** завдяки порівнянню `participant.id === guestSessionId`.
  * **Консолідація замовлення:** за допомогою хелпера `consolidatePreOrder` реалізовано об'єднання однакових страв в один список для ресторану (`Назва страви × Кількість`).
  * **Підрахунок Grand Total:** сума рахується виключно за підтвердженими кошиками ($540.00, а не загальні $760.00).
  * **Інформаційні стани:**
    * Жовта плашка-попередження, якщо хтось із гостей ще не підтвердив свій вибір.
    * Порожній стан (*«Participants haven’t added any dishes yet»*).
    * Лоадер під час початкового завантаження та екран помилки (404: *«Group reservation not found»*, 500: кнопка *«Try again»*).
* **Модальне вікно та підтвердження:**
  * Використано спільний компонент `<app-modal>` для підтвердження відправки замовлення.
  * Захищено запит від подвійного натискання (блокування кнопки під час запиту).
  * Після підтвердження статус змінюється на `Sent to Restaurant`, екран стає read-only, а користувачу показується успішний Toast.

---

### 3. 3-й рівень — Інтеграція з AWS API та фонова синхронізація
* **Інтеграція з реальним бекендом:**
  * У `src/environments/environment.development.ts` налаштовано зв'язок із власним сервером в AWS API Gateway (`eu-north-1`).
* **Фонова синхронізація (Background Sync):**
  * Поки статус замовлення `Open`, сторінка кожні 15 секунд фоново опитує сервер для отримання свіжих кошиків гостей.
  * Використано `exhaustMap`, що унеможливлює накладання запитів, якщо попередній ще не завершився.
  * Запити є «тихими» завдяки `HttpContext` та `SKIP_ERROR_TOAST` (користувач не бачить червоних помилок на випадок короткочасного збою зв'язку).
  * Дані оновлюються плавно — без перезавантаження та без лоадера на весь екран.
  * Реалізовано рядок стану `Updated at HH:mm:ss` (або `Couldn’t refresh...` при збої) та кнопку примусового оновлення **«Refresh»**.
  * Очищення підписки (`ngOnDestroy`) запобігає витокам пам'яті при виході зі сторінки.

---

### 4. Бонусне завдання — Remove Guest
* Для організатора додано функціонал видалення гостя зі спільного бронювання (`DELETE /guest/groups/{id}/sessions/{guestSessionId}`).
* Кнопка **«Remove Guest»** відображається лише біля гостей (біля картки овнера її немає, а після відправки замовлення вона блокується).
* Діалогове вікно підтвердження попереджає про незворотність дії з персоналізованим зверненням по імені гостя.
* Після видалення оновлений список повертається із сервера, а суми автоматично перераховуються.
